databases/duckport: DuckDB SQL engine run as an Erlang port
===========================================================

New port. duckport runs SQL against a DuckDB database file, reading
requests on standard input and writing JSON on standard output.

- Line mode: one SQL statement per line, answered with
  {"rows":[...]} or {"error":"..."}.
- --jsonl: the operations query (SQL with typed parameters, at most
  1000 rows) and batch (statements in one transaction).

With --jsonl it speaks the request protocol described in beamports'
README: one JSON object per line each way, a version and a request_id
that the reply repeats, at most 16 MiB per line, and success reported
only once the change is durable. jsonl_port, in the same repository, is
the Elixir client for it; it is not ported on its own, since
applications compile it in.

Overlay: https://github.com/yoonka/freebsd-ports-overlay
(databases/duckport)


Version
-------

1.1.0, from the tag v1.1.0 of beamports
(https://github.com/yoonka/beamports, BSD-3-Clause). beamports holds
several programs and their Elixir clients, one directory each, and a
tag releases all of them at one version. Its four ports
(sysutils/knotify, databases/duckport, databases/oxiport,
databases/tantiport) share the version and the source settings in
sysutils/knotify/Makefile.beamports and move to a new tag together.
They fetch the same distfile, the whole repository (about 100 kB), and
each builds in its own directory (WRKSRC_SUBDIR=${PORTNAME});
LICENSE_FILE is the repository's LICENSE one level up. Before 1.1.0, duckport was developed in a private
repository.


The port
--------

- USES=cargo; Makefile.crates generated from upstream's Cargo.lock
  (146 crates).
- DuckDB 2.0.0 is compiled from the duckdb crate's bundled C++ source
  (libduckdb-sys "bundled"), so nothing is downloaded at build time and
  no databases/duckdb is needed. Upstream turns the crate's default
  features off: they only add an HTTP/TLS stack for downloading a
  prebuilt library.
- Installs bin/duckport.
- No patches.

DuckDB 2.0 opens files written by DuckDB 1.x and keeps their format;
new files get the 2.0 format, which 1.x cannot read.


Tested
------

With 1.1.0 (the tag v1.1.0 of beamports), on FreeBSD 15.1 amd64 with
lang/rust 1.99.1:

- poudriere testport: build, stage-qa and check-plist clean; package,
  install and deinstall pass.
- The binary built by the port, with --jsonl: a batch creating a table
  and inserting a row with a parameter was committed, and a query read
  the row back; version() reports v2.0.0.
- Before the port, from the same source: upstream's test, and every
  operation and error case its README lists, including a database file
  written by DuckDB 1.4.

Not tested: aarch64 and other architectures.
