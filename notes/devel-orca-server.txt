devel/orca-server: Orca's server-only release on FreeBSD's node
================================================================

New port, draft. It packages Orca's server, orcad
(https://github.com/stablyai/orca, MIT), from the server-only tarball
upstream publishes with every release. Orca is an Electron "agent IDE"
that runs coding agents such as Claude Code, Codex and OpenCode in git
worktrees and terminals. The server keeps the projects, worktrees,
terminals and agent sessions. The UI is provided by paired clients:

- the Orca desktop app on Linux, macOS or Windows (Settings -> Remote
  Orca Servers -> Add Server);
- the Orca mobile app.

The browser client is not included: upstream ships it only with the
desktop app ("A server-only install has no browser panes, dictation or
paired web client, because those come with the desktop app",
docs/site/content/docs/remote-servers.mdx). devel/orca-ide takes the
server and the browser client from the desktop .deb, and is meant to
become the desktop port.

Overlay: https://github.com/yoonka/freebsd-ports-overlay
(devel/orca-server)

The server code, its FreeBSD fixes and the service are the same as in
devel/orca-ide, and notes/devel-orca-ide.txt describes them in full:
what `orca serve` is, the ps(1) column-list shim (files/freebsd-compat.cjs
and the build-time check files/check-ps-calls.cjs), the stale instance
lock (bin/orca-ide), the environment, and the rc script on daemon -u.
This file covers what differs.


Names
-----

- Package orca-server, after upstream's orca-server-linux-<arch>.tar.gz
  and its install directory /opt/orca-server.
- Command bin/orca-ide, as in upstream's server tarball (bin/orca-ide)
  and its Linux packages: accessibility/orca owns bin/orca.
- rc script orca_server, rcvars orca_server_*.
- Installed under lib/orca-server.

devel/orca-ide and devel/orca-server conflict (CONFLICTS_INSTALL): both
install bin/orca-ide and serve on port 6768. They share the user and
group orca (593, home /var/db/orca), and a profile in the service
user's home works with either, so moving from one to the other keeps
the paired clients. Only the rc.conf variables are renamed.


How the port is built
---------------------

There is no source build of the JavaScript, for the reasons in
notes/devel-orca-ide.txt.

Distfiles, all in distinfo, under DIST_SUBDIR orca-server/<version>:

- orca-server-linux-x64.tar.gz, the release's server tarball (about
  61 MiB, against 195 MiB for the .deb). The same file is used on every
  architecture. Its name does not carry the version, hence the
  per-version DIST_SUBDIR. upstream publishes its SHA-256 in
  orca-server-sha256sums.txt, which find-new-version prints.
- node-pty-1.1.0.tgz, watcher-2.5.6.tgz and node-addon-api-7.1.1.tgz
  from the npm registry, and node-pty@1.1.0.patch from the release tag,
  exactly as in devel/orca-ide.
- The LICENSE comes from the tarball.

The tarball holds:

- orcad/: upstream's server package. For 1.4.258 it is byte for byte
  the .deb's resources/orcad-template (without its manifest) plus the
  linux-x64-glibc target's files (the node-pty and @parcel/watcher
  addons and the markers .runtime-node and .server-target, also
  identical to the .deb's), a Linux ripgrep under ripgrep/linux-x64/,
  and a .version marker;
- runtimes/: the Node binary upstream pins;
- bin/orca-ide: a launcher for that Node;
- out/main/orcad/orcad-local-serve-selection-entry.js, used by the
  desktop CLI to choose a runtime;
- VERSION, naming the release, orcad's version, Node and the target.

scripts/post-extract:

- extracts VERSION, LICENSE and orcad/ only, which leaves out the pinned
  Node, the bulk of the tarball;
- installs orcad/ without the three markers, the Linux binaries and
  ripgrep's licences;
- fails the build if any of its assumptions changes:
  - VERSION names another release or another target;
  - out/package.json's version against DISTVERSION;
  - the tarball's node-pty version against NODE_PTY_VERSION;
  - the ELF files in orcad/ against the three it replaces (pty.node,
    watcher.node, rg), where a new entry would most likely be a new
    native addon;
  - any of the three markers missing.

All three markers have to go. orcad.js treats any one of .runtime-node,
.server-target and .version as a packaged install; with .version left in
place and the other two removed it refuses to start ("The bundled Orca
runtime target is missing"). Without any of them it runs "unpackaged"
on the system node, orcad's own path (orcad-bundled-runtime.ts).

do-build, do-install, ripgrep (a symlink to textproc/ripgrep's rg) and
the ps check are as in devel/orca-ide. post-install lists only the
mobile web bundle's hashed assets and catalogs; there is no web client.

files/orca-ide.in, files/freebsd-compat.cjs and files/check-ps-calls.cjs
are identical to devel/orca-ide's. The launcher passes --web-client-root
only when web/web-index.html is installed, and gets the rc script's name
from SUB_LIST. files/orca_server.in is devel/orca-ide's orca_ide.in with
the names changed. Keep them in step when either port changes.


Service
-------

As in devel/orca-ide, with orca_server in place of orca_ide:
daemon(8) runs as root and starts orcad as orca_server_user (daemon -u);
the pid file is /var/run/orca_server.pid and the log
/var/log/orca_server.log, both root's. `service orca_server pair` prints
the "Pairing URL" only; there is no "Web client URL".


How to update
-------------

1. `make find-new-version`. It sets DISTVERSION and the native module
   versions from the latest release's pnpm-lock.yaml, as in
   devel/orca-ide, and prints the SHA-256s that the node-pty patch and
   the server tarball must have.
2. makesum. Check distinfo's SHA256 for node-pty@<version>.patch and for
   orca-server-linux-x64.tar.gz against the printed values.
3. testport. It stops at the first assumption that no longer holds:
   post-extract's checks, the node-pty patch or the addon builds,
   check-ps-calls.cjs, and check-plist.
4. Smoke test in a jail: "PTY self-test passed" in the readiness lines,
   `service orca_server pair` prints the pairing link, and closing a
   terminal kills its background jobs.

Update devel/orca-ide to the same release at the same time, so that the
shared files stay in step.


Tested
------

With 1.4.258, on FreeBSD 15.1 amd64 with www/node24 24.22.1:

- poudriere testport: build, stage-qa and check-plist clean;
  package, install and deinstall pass. check-ps-calls.cjs: 59 ps
  column lists, all rewritten (as in devel/orca-ide).
- In poudriere's own jail, left running by testport -I with the package
  and its run dependencies installed, orcad bound to 127.0.0.1:
  - service start: daemon(8) as root, orcad and its terminal daemon as
    orca; "Orca server ready" and "Terminal daemon: live -- PTY
    self-test passed (pty-spawn: healthy)".
  - `service orca_server pair` prints the pairing link.
  - CLI: `status`, `repo add`, `terminal create` with a command that
    starts a background job, `terminal read` and `terminal close`.
    Closing the terminal killed the background job.

Not tested: aarch64.
